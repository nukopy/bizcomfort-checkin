# MVP

2026-10-26 の範囲は、拠点に行って QR を読み、ドアが解除されるところまで。ユーザーがやることはそれだけ。

一番大事なのは、パスワードとログインを毎回入力しないこと。

## 画面

三つのタブ。

1. QR コード読み取り。起動直後に開いているタブ
2. ログ。当日が含まれる 1 か月
3. 設定。メールアドレスとパスワード。その下に「アクセス許可」を出し、位置情報の状態を見る

## ログ

開いたときは、今日が属する月だけを出す。ページ上部は `2026 年 3 月` の形。月が変わると、この表示と一覧が変わる。

右上の検索ボタンで月を選ぶ。候補は新しい月が上で、リリース日の月で止まる。並びは次のとおり。

```text
2026 年 3 月
2026 年 2 月
2026 年 1 月
2025 年 12 月
```

全件表示はしない。月ごとの件数は少ないので、ページングもしない。もっとも過去の月はアプリのリリース日で固定する。日付は `lib/constants.dart` の `appReleaseDate` で、値は 2026-10-26。この値のあいだは、いちばん下が `2026 年 10 月` になる。

ログは端末内に保存し、アプリを終了しても残す。

解除の成功も失敗も、必ず 1 件残す。記録の `status` は `SUCCESS` か `FAILED` のどちらか。

一覧の 1 行は、日付、時刻、GPS の緯度経度から引いた市区町村、`enter` または `exit`、`status`。入退室は URL のパスから判断する。市区町村は「東京都大田区」まででよい。位置情報の許可はユーザーに求める。許可されなければ市区町村の欄は `NOT_PERMITTED`、逆引きできなければ `FAILED`、取れていれば市区町村を出す。この `FAILED` は市区町村の欄で、解除結果の `FAILED` とは別の列である。許可が無いときの緯度経度は空にする。

行のボタンで詳細へ進む。タブは出したまま、ログタブの中で開く。詳細は一覧の情報に加え、URL と緯度経度を出す。

## 読み取り

- QR コードリーダーはアプリの中にある
- アプリを起動した時点で、リーダーがすでに起動している。アプリを開いてからリーダーを開く、という二段にはしない
- メールアドレスとパスワードが未設定なら、読み取り面に「メールアドレス、パスワードが設定されていません」と、設定タブへ移るボタンを出す。この移動はアプリ内のタブ切り替えで、ディープリンクは使わない
- 読み取ったあとのログインは裏側で行う。パスワードをその場で打たせない
- ログインセッションはモバイルアプリが維持する
- セッションが切れていても、ユーザーはメールアドレスとパスワードを打ち直さない。アプリが保存済みの認証情報でセッションを取り直す
- 解除に失敗したときは「解除に失敗しました」とポップアップを出す。ページからエラーメッセージを取り出せたときだけ、同じポップアップにそれを足す。取り出せなければ、その文だけにする。WebView は出さない

## 認証情報とログイン

メールアドレスとパスワードは、スマホ側に暗号化して保存する。保存先は OS の安全なストレージで、`flutter_secure_storage` を使う。ログイン用の WebView は `flutter_inappwebview` を使う。

この段階ではパッケージを入れない。実装に入るときに次を実行する。

```sh
flutter pub add flutter_inappwebview
flutter pub add flutter_secure_storage
flutter pub add geolocator
```

`geolocator` は、設定タブの位置情報の許可と、ログに残す緯度経度に使う。

未ログインで解除 URL を開くと、`/login?next=<元のパス>` へ移る。セッションの有無はサーバが Cookie で判断する。ログインへ飛ばなければセッションは生きている。飛ばされたときだけ、保存済みの認証情報でログインし、`next` の解除 URL へ戻る。

ログインの流れ:

1. OS の安全なストレージから認証情報を取得する。
2. 正しい HTTPS サイトが表示されていることを確認する。
3. WebView のフォームに認証情報を入力する。欄は `#id_email` と `#id_password`、確定は `input.form-btn`。
4. ユーザーがログインを確定する。
5. ログイン後はパスワードではなく、WebView のセッションを利用する。

QR の URL は GET で開くページに見える。ログインと解除の WebView は読み取りタブの裏に置き、画面には出さない。

位置情報は二段ある。アプリ自身の許可は、設定タブの「アクセス許可」で見る。未許可ならそこから許可を求める。OS が拒否したあとは、端末の設定を開く。解除ページが WebView の中で位置情報を求める応答は、アプリが代わりに返せる。返してよいのは `https://mypage.bizcomfort.jp` だけで、かつアプリの位置情報がすでに許可されているときだけである。この応答は OS の許可ダイアログの代わりにはならない。許可が無ければ、ページは位置を取れない。許可の確認はアプリ側で先に行う。
